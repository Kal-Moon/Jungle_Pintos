## 1. 10/18 (일) 밤 — 준비 학습

- [ ] KAIST 문서 **System Calls** 앞부분: 유저 프로그램이 시스템 콜을 부르면 커널 어디로 들어오는지, 인자가 어느 레지스터에 오는지
  - 번호는 `f->R.rax`, 인자는 순서대로 `rdi`, `rsi`, `rdx`, `r10`, `r8`, `r9`, 반환값은 `f->R.rax`에 쓴다
- [ ] `halt`, `exit`, `write` 명세 읽기. `write`는 fd 1이면 `putbuf()`를 **한 번에** 호출
- [ ] **Process Termination Messages**: 출력 형식, 출력하지 않는 경우(커널 스레드, `halt`)
- [ ] `process_create_initd()`에서 스레드 이름이 커맨드라인 전체로 들어가는 것 확인 → 어디서 자를지 생각해 오기
- [ ] `userprog/exception.c`의 `page_fault()` 읽고, 유저 코드에서 난 fault를 어떻게 구분하는지 찾기
- [ ] `is_user_vaddr()`(`include/threads/vaddr.h`), `pml4_get_page()`(`threads/mmu.c`)가 무엇을 해 주는지

**뼈대 회의에 가져갈 의견**
- [ ] 검증 함수 3개 이름·인자: 주소 1개 / 버퍼(주소 + 크기) / 문자열
- [ ] 종료 메시지 출력 위치: 정상 `exit`과 커널 강제 종료가 **둘 다 지나가는** 함수

## 2. 10/19 (월) — 오전 머지가 최우선 ⭐

10:00~10:15 짧은 회의(어제 한 것 / 오늘 할 것 / 막힌 것) 후 시작.

### 오전: `feat/syscall-basic/이니셜`

| 시간 | 할 일 | 확인 테스트 |
|---|---|---|
| 10:15~10:45 | `sys_halt`: `power_off()` | `halt` |
| 10:45~11:15 | `sys_write`: fd 1이면 버퍼를 `putbuf()` 한 번으로 출력, 쓴 바이트 수를 `rax`에. fd 1이 아니면 **B 몫으로 비워 둠** | `(args) begin` 같은 출력이 보임 |
| 11:15~11:40 | `sys_exit`: 종료 상태를 뼈대 필드에 저장하고 `thread_exit()` | |
| 11:40~12:00 | 종료 메시지 `프로그램이름: exit(상태)` 를 **한 번만**. 커널 스레드는 출력 X. 스레드 이름이 커맨드라인 전체면 첫 단어만 → **PR → 머지** | `args-*`, `halt`, `exit` (C의 wait과 함께) |

**종료 메시지 구현 메모**
- 형식은 정확히 `printf ("%s: exit(%d)\n", 이름, 상태);` — 테스트 `.ck`가 이 한 줄로 채점한다
- `process_exit()`은 커널 스레드가 끝날 때도 불릴 수 있다 → **유저 프로세스일 때만** 찍히게 조건 필요
- `halt`로 끝날 때는 출력하지 않는다
- 이름 자르기: `process.c:54`에서 첫 단어만 이름으로 넘긴다
  - `strtok_r`는 원본을 바꾸므로 **복사본**에서 자를 것
  - `fn_copy`는 `initd`로 그대로 넘어가야 하니 건드리지 않는다 (인자 전달이 깨짐)
- `process_exit()`은 셋이 같이 고친다. 내 블록은 **맨 앞**에 두고 위에 `/* 종료 메시지. */` 주석
  - 순서: 종료 메시지(A) → 파일 정리(B) → 부모 깨우기(C)

### 오후: `feat/user-memory/이니셜`

| 시간 | 할 일 | 확인 테스트 |
|---|---|---|
| 13:00~15:00 | 검증 함수 1: 주소 하나 검사. NULL, 커널 영역(`is_user_vaddr` 거짓), 매핑 안 됨(`pml4_get_page`가 NULL)이면 `exit(-1)` | `*-null`, `*-bad-ptr` |
| 15:00~17:00 | 검증 함수 2: 버퍼(시작 ~ 시작+크기-1)와 문자열(`\0`까지)을 끝까지 검사. **페이지 경계에 걸치는 경우** 포함. `sys_write`에 적용 | `*-boundary`, `sc-*` |
| 17:00~19:00 | `page_fault()`: 유저 코드에서 난 fault면 종료 상태 -1로 프로세스 종료 | `bad-read`, `bad-write`, `bad-jump` |
| 19:00~21:00 | 회귀 확인 → **PR** | 오전에 통과한 테스트 여전히 PASS |
| 21:00~22:00 | 서로 PR 리뷰 → 머지 → 최신 `main` 받기 | |

**꼭 맞출 것**
- 검증 실패로 `exit(-1)` 할 때 **파일 시스템 락을 잡고 있으면 안 된다** → B(준우)와 "**락 잡기 전에 검증**"으로 맞춤
- `page_fault`에서 종료 상태 -1을 남겨야 C(민희)의 `wait-killed`가 통과 → 민희와 맞춤
- 확인용 `printf`가 하나라도 남으면 **모든 테스트 FAIL**. 기존 `"system call!"` 출력도 지워져 있어야 함

## 3. 10/20 (화) — exec + C 지원

브랜치: `feat/exec/이니셜`

| 시간 | 할 일 | 확인 테스트 |
|---|---|---|
| 10:15~13:00 | `sys_exec`: 커맨드라인 문자열 검증 → **새 페이지에 복사** → `process_exec()` 호출. 실패하면 종료 상태 -1로 종료. 성공하면 돌아오지 않음. fd와 스레드 이름은 유지 | `exec-once`, `exec-arg`, `exec-boundary`, `exec-missing`, `exec-bad-ptr` |
| 13:00~15:00 | 종료 메시지가 **모든 종료 경로**(정상 `exit`, `page_fault`, 검증 실패, exec 실패)에서 정확히 한 번 찍히는지 | 모든 `.ck` 마지막 줄 |
| 15:00~21:00 | C(민희)와 합류: fork·wait 남은 테스트, 해제 경로 점검 | `fork-*`, `wait-*` |

- 왜 새 페이지에 복사하나: `process_exec`가 **현재 주소 공간을 지우기 때문에**, 유저 메모리에 있던 원본 문자열은 그 뒤에 못 읽는다
- 화요일 저녁 머지 순서는 **B → C → A** (나는 마지막). 앞 두 개가 머지되면 최신 `main`을 받아 충돌 정리 후 머지

## 5. 내가 자주 쓸 명령

`pintos/userprog/build`에서:

| 목적 | 명령 |
|---|---|
| 빌드 | `make` |
| 테스트 1개 결과 | `make tests/userprog/halt.result` (이름만 바꿔서) |
| 테스트 1개 화면으로 | `pintos --fs-disk=10 -p tests/userprog/args-single:args-single -- -q -f run 'args-single onearg'` |
| 전체 | `make check` |
| 결과 지우고 다시 | `rm -f tests/userprog/*.result` |

Git:

| 목적 | 명령 |
|---|---|
| 동료가 올린 최신 `main` 받기 | `git checkout main && git pull origin main` |
| 작업 중 내 브랜치에 최신 `main` 반영 | `git pull origin main` (내 브랜치에서) |
| 새 브랜치 | `git checkout -b feat/기능/이니셜` |
| 내 작업 올리기 | `git add 파일` → `git commit` → `git push -u origin 브랜치이름` |

- **받기 = `pull`, 올리기 = `push`**
- PR 설명에 새로 통과한 테스트와 깨진 테스트 **이름**을 적는다
- 30분 넘게 막히면 팀 채널에 실행 명령, 출력(패닉 메시지 포함), 의심 위치를 같이 올린다
