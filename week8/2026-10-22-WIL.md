## 0. 큰 그림 — 코치님 강의

### 갇혀 있는 프로세스

- CPU가 실행하며 내는 주소는 **전부 가상 주소**다. 진짜 물리 주소는 하드웨어(MMU)가 몰래 번역해 준다.
- 가상 주소 공간은 `KERN_BASE`를 기준으로 위는 커널, 아래는 유저 영역이다.
- 유저 프로그램은 **Ring 3(유저 모드)** 로 돌기 때문에 커널 영역에 직접 접근할 수 없다. 넘어가는 유일한 정식 통로가 **시스템 콜**이다.

### PML4: 48비트 주소를 4단계로 번역

```
 47      39 38     30 29     21 20     12 11          0
┌─────────┬─────────┬─────────┬─────────┬─────────────┐
│  PML4   │  PDPT   │   PD    │   PT    │   offset    │
│  9비트   │  9비트   │  9비트   │  9비트   │   12비트     │
└─────────┴─────────┴─────────┴─────────┴─────────────┘
```

- 9비트 → 테이블 하나에 512칸, 한 칸이 8바이트 → 512 × 8B = **4KB, 테이블 하나가 페이지 하나**에 딱 맞는다.
- 같은 물리 페이지가 커널에게는 **KVA**(`물리주소 + KERN_BASE`)로, 유저에게는 **UVA**로 보인다. 실체는 하나.

### 모든 것은 파일

| fd | 대상 |
|---|---|
| 0 | 키보드 (stdin) |
| 1 | 화면 (stdout) |
| 2~ | `open`으로 연 파일 |

장치든 파일이든 `open` / `read` / `write` / `close` 네 개로 다룬다.

### 로드맵

**인자 전달 → 시스템 콜(`write`, `exit`) → 파일 시스템 콜 → 프로세스 관리(`fork`, `exec`, `wait`)**
인자 전달이 맞았는지 확인하려면 결과를 **출력(`write`)** 하고 **끝나야(`exit`)** 하기 때문에, 인자 전달과 기본 시스템 콜은 같이 붙어 다닌다.

## 1. 기본 시스템 콜 — `halt`, `exit`, `write`, 종료 메시지

### 시스템 콜이 커널로 들어오는 길

```
halt.c          halt ()
lib/user        syscall0 (SYS_HALT) → rax = 번호 → syscall 명령
────────────── 유저 / 커널 경계 ──────────────
syscall.c       syscall_handler (f)  →  switch (f->R.rax)
syscall.c       sys_halt ()  →  power_off ()
```

| 무엇 | 레지스터 |
|---|---|
| 시스템 콜 번호 | `rax` |
| 인자 1~6 | `rdi`, `rsi`, `rdx`, `r10`, `r8`, `r9` |
| 반환값 | `f->R.rax`에 써 넣기 |

> 은행 창구 비유: 손님(유저)은 금고(하드웨어)에 못 들어간다. **번호표**(시스템 콜 번호)와 **신청서**(인자)를 창구(커널)에 내면 직원이 대신 처리하고 **영수증**(반환값)을 준다.

### `write` (fd 1)

```c
/* fd 1 은 콘솔. 여러 번 나눠 출력하면 다른 프로세스 출력과 섞일 수 있어
   콘솔 락을 한 번만 잡는 putbuf () 로 한 번에 출력한다. */
if (fd == 1) {
	putbuf (buffer, size);
	return size;
}
```

### 종료 메시지

```c
/* 페이지 테이블 (pml4) 이 있는 스레드만 유저 프로세스이므로 커널 스레드는 찍지 않는다.
   process_cleanup () 이 pml4 를 지우기 전에 확인한다. */
if (curr->pml4 != NULL)
	printf ("%s: exit(%d)\n", curr->name, curr->exit_status);
```

- **이름은 프로그램 이름만.** `args-single onearg`로 실행해도 `args-single: exit(0)`이어야 한다. 그래서 `process_create_initd()`에서 이름용 복사본을 따로 만들어 첫 단어만 잘라 스레드 이름으로 넘겼다.
- **`halt`는 찍지 않는다.** 프로세스가 끝나는 게 아니라 컴퓨터가 꺼지는 것이라 `process_exit()`을 지나지 않는다.
- **모든 종료 경로가 한 곳으로 모인다.** 정상 `exit`, `page_fault`, 검증 실패, `exec` 실패 모두 `sys_exit (값)` → `thread_exit()` → `process_exit()`을 지나서, 메시지가 **정확히 한 번** 찍힌다.

### 🐛 삽질

- `#include init.h`처럼 **따옴표 없이** include를 써서 빌드가 실패했다. 빌드가 안 되면 테스트는 돌아보지도 못한다.
- `halt`만 넣고 테스트했더니 `missing 'begin' message`로 FAIL. `(halt) begin`도 결국 유저 프로그램이 `write`로 찍는 것이라, **`write`가 없으면 아무것도 안 보인다.**
- 테스트 결과가 몇 번을 고쳐도 **처음과 글자 하나까지 똑같았다.** 알고 보니 `sys_exit`을 뼈대에 이미 있는데 `static`으로 한 번 더 만들어서 **빌드가 계속 실패**했고, `build` 폴더에 남은 **예전 커널**로 테스트하고 있었다. → 결과가 이상하면 `kernel.bin` 시간부터 확인하기.
- `power_off()` 아래에 뼈대의 자리 채움 코드 `sys_exit (-1);`이 남아 있었다. `power_off()`는 돌아오지 않으니 **절대 실행되지 않는 줄**이라 지웠다.

## 2. 유저 메모리 검증 — 유저가 준 주소를 믿지 않기

### 왜 필요한가

시스템 콜을 처리하는 동안 CPU는 **커널 모드**라서 커널 메모리도 읽을 수 있다. 그런데 유저가 이렇게 부르면?

```c
write (1, (void *) 0x8004000000, 100);   /* 커널 영역 주소를 버퍼로 넘김 */
```

- 커널이 검사 없이 읽으면 **커널 메모리가 화면에 새어 나간다.**
- NULL이나 매핑 안 된 주소면 **커널 안에서 page fault**가 나서 OS 전체가 멈춘다. 잘못한 건 유저인데!

### 검증 함수 3개

| 함수 | 검사 대상 |
|---|---|
| `validate_user_addr` | 주소 하나: NULL / 커널 영역 / 매핑 안 됨 → `exit(-1)` |
| `validate_user_buffer` | 버퍼 전체 (시작 ~ 시작+크기-1) |
| `validate_user_string` | 문자열 (`'\0'`까지) |

```c
void
validate_user_addr (const void *uaddr) {
	/* pml4_get_page () 는 커널 주소를 넘기면 ASSERT 로 멈추므로 커널 영역 검사를 먼저 한다. */
	if (uaddr == NULL || !is_user_vaddr (uaddr)
			|| pml4_get_page (thread_current ()->pml4, uaddr) == NULL)
		sys_exit (-1);
}
```

### `page_fault`: 유저 잘못이면 그 프로세스만

```c
/* 유저 코드가 잘못된 주소를 건드린 것은 커널 문제가 아니라 그 프로세스의 잘못이므로,
   커널을 멈추지 않고 그 프로세스만 종료 상태 -1 로 끝낸다. */
if (user)
	sys_exit (-1);
```

이건 퀴즈 풀듯 답만 받지 않고 **내가 로직을 먼저 짜고 도움을 받는 방식**으로 구현했다. (`bool user`를 어디서 쓰는지, `#ifdef VM` 블록과의 위치 등)

### 배운 점

- **검사 순서가 곧 안전장치다.** `||`의 단락 평가 덕분에 `is_user_vaddr()`에서 걸리면 `pml4_get_page()`는 불리지 않는다.
- **버퍼는 시작 주소만 보면 안 된다.** 시작은 멀쩡해도 끝이 매핑 안 된 페이지에 걸칠 수 있다. 매핑은 페이지 단위이니 **걸친 페이지마다 한 번씩**만 보면 된다.
- **검증은 락 잡기 전에.** 파일 시스템 락을 쥔 채 `exit(-1)` 하면 락이 영원히 안 풀린다. 그래서 팀 규칙으로 "유저 포인터 검증은 락 잡기 전에"를 정했다.
- 같은 과제를 한 다른 사람의 코드와 비교해 보니, `page_fault` 처리가 없으면 `bad-read` 같은 테스트에서 `exit(-1)`이 아니라 `exit(0)`이 찍혀 FAIL이 난다. **이 한 줄이 `bad-*` 테스트 6개를 가른다.**

## 3. `exec` — 현재 프로세스를 다른 프로그램으로 바꾸기

### 짠 코드

```c
static int
sys_exec (const char *cmd_line) {
	char *cmd_copy;

	/* 커널이 문자열을 읽기 전에 검사한다. 잘못된 주소면 이 프로세스만 끝난다. */
	validate_user_string (cmd_line);

	/* process_exec () 는 load 전에 지금 유저 메모리를 지우고, 끝나면 받은 문자열을
	   페이지로 해제한다. 그래서 유저 문자열을 그대로 넘기지 않고 커널 페이지에 복사한다. */
	cmd_copy = palloc_get_page (0);
	if (cmd_copy == NULL)
		sys_exit (-1);
	strlcpy (cmd_copy, cmd_line, PGSIZE);

	/* 돌아왔다면 로드에 실패한 것이다. cmd_copy 는 process_exec () 안에서 이미 해제됐다. */
	if (process_exec (cmd_copy) < 0)
		sys_exit (-1);
	return -1;
}
```

### 왜 복사해야 하나

```
process_exec (cmd_line)
 ├─ process_cleanup ()   ← 유저 메모리 폐기. "child-simple" 글자도 같이 사라짐
 └─ load (cmd_line)      ← 사라진 주소를 읽음 → 커널 page fault → 핀토스 정지
```

> 이사 가는 날 옛집이 철거되는데 중요한 서류가 옛집에 있는 상황. 주소만 적어 가면 소용없고, **서류를 복사해서 내 가방(커널 페이지)에 넣어 가야** 한다.

### 배운 점

- **유저 메모리를 꼭 버려야 하는 이유**: 모든 프로그램의 스택 자리(`USER_STACK` 바로 아래)가 똑같다. 옛 메모리를 안 버리면 `setup_stack`의 `install_page`가 "이미 쓰는 주소"라며 거부해서 `load`가 실패한다.
- **`palloc_get_page (0)`의 `0`** 은 "빈 값"이 아니라 **옵션 스위치를 하나도 안 켰다**는 뜻이다. `PAL_USER`(4)가 꺼져 있으니 커널 풀에서 받는다. `PAL_ASSERT`도 일부러 안 켰다. 켜면 메모리가 없을 때 핀토스 전체가 멈추지만, 안 켜면 그 프로세스만 끝낼 수 있다.
- **마지막 `return -1;`은 실행되지 않는다.** 성공하면 `do_iret`로 새 프로그램에 점프해서 돌아오지 않고, 실패하면 위에서 `sys_exit`로 끝난다. 반환형이 `int`라 컴파일러를 위해 둔 줄이다.
- **exec 후에도 남는 것**: `process_cleanup()`은 `pml4`만 지운다. 스레드 이름, tid, 열린 fd는 `struct thread`에 있어서 그대로다. 그래서 `exec-once`에서 `child-simple`이 돌았는데도 마지막 줄은 `exec-once: exit(81)`이다.

## 4. 파일 입출력 — 팀원 파트를 이어서

팀원이 `create`·`remove`·`open`·`close`와 fd 테이블을 만들었고, 나는 이어서 `filesize`·`read`·`write`(파일)·`seek`·`tell`을 구현했다.

### `read`

```c
static int
sys_read (int fd, void *buffer, unsigned size) {
	struct file *file;
	int bytes;

	validate_user_buffer (buffer, size);

	/* fd 0 은 키보드. 파일 시스템을 쓰지 않으므로 락이 필요 없다. */
	if (fd == 0) {
		uint8_t *p = buffer;

		for (unsigned i = 0; i < size; i++)
			p[i] = input_getc ();
		return size;
	}

	file = fd_lookup (fd);
	if (file == NULL)
		return -1;

	lock_acquire (&filesys_lock);
	bytes = file_read (file, buffer, size);
	lock_release (&filesys_lock);
	return bytes;
}
```

### 배운 점

- **`void *`는 한 칸의 크기를 모른다.** `buffer[i]`도 `buffer++`도 안 된다. `uint8_t *`(바이트 포인터)에 옮겨 담아서 한 칸씩 쓴다. 처음엔 재귀로 해야 하나 했는데, 그냥 `for` 반복문이었다.
- **분기 순서로 코드를 줄일 수 있다.** `fd_lookup()`은 0, 1에 NULL을 돌려준다. 그래서 fd 0만 먼저 처리하고 나머지를 `fd_lookup()`에 맡기면 "fd 1은 실패"를 따로 검사할 필요가 없다.
- **`seek`의 숨은 함정**: `file_seek()`는 `off_t`(32비트 정수)를 받는다. 유저가 `0x80000000` 같은 큰 값을 넘기면 음수로 바뀌어서 `ASSERT`로 **커널이 멈춘다.** 그래서 `position > INT32_MAX`면 무시하도록 조건을 추가했다.
- `sys_seek`는 `void`라 값을 돌려줄 수 없고, `file_seek()`도 돌려주는 값이 없다. 반대로 `sys_tell`은 `file_tell()`의 값을 돌려줘야 한다. **함수 머리(반환형)부터 확인하고 몸통을 쓰자.**

## 5. 협업 — 포크, PR, merge 충돌

이번 주는 개인 포크 저장소에서 브랜치를 따서 팀 저장소로 PR을 올리는 방식이었다.

```
compare (보내는 쪽)                        base (받는 쪽)
Kal-Moon/JungleWeek08 : feat/args/sk  →  cocham/JungleWeek08 : main
         내 작업                              팀 최종본
```

### 🐛 삽질

- PR 화면에서 자꾸 같은 브랜치끼리 비교됐다. **`compare across forks`** 로 바꿔야 포크 → 팀 저장소 PR이 된다. base는 "받는 쪽", compare는 "보내는 쪽"이라고 외웠다.
- 팀원 PR과 내 PR이 **`process_exit()`의 같은 자리**(원래 TODO 주석이 있던 곳)를 각자 고쳐서 충돌이 났다. 내용이 틀려서가 아니라 git이 "둘 중 뭘 쓸지" 묻는 것이라 **둘 다 남기고** 순서만 정했다: 종료 메시지 → fd 정리 → `process_cleanup()`.
- 충돌을 해결하다가 **Ctrl+Z로 되돌려서 초기화**됐다. `git checkout -m 파일`로 충돌 직후 상태를 다시 만들 수 있다는 걸 배웠다. `git add` 전이라면 언제든 `git merge --abort`로 처음부터 다시 할 수 있다.
- merge를 **커밋하기 전에** 새 브랜치를 만들면 git이 "merge 중"이라는 정보를 잃어서 팀원 커밋 기록이 빠진다. 먼저 커밋하고 브랜치를 땄다.
- 파일을 웹에서 통째로 업로드하다가 **`page_fault` 수정이 빠진 채 올라간** 적이 있다. 다음 날 따로 커밋해서 메웠다.

### 테스트할 때의 함정

- `process_wait()`이 아직 팀원 담당이라 바로 `-1`을 돌려준다. 그러면 유저 프로그램이 출력도 하기 전에 핀토스가 꺼져서 **모든 테스트가 FAIL**이다.
- 테스트할 때만 `timer_sleep (300);`을 임시로 넣었다. `while (1);`은 핀토스가 안 꺼져서 `make check`에서는 못 쓴다.
- 임시 함수를 `syscall.c`에 하나 더 만들었다가 `multiple definition of 'process_wait'` 링크 에러가 났다. 이미 있는 함수를 고쳐야 한다.

## 7. 이번 주에 가장 많이 헷갈렸던 것

| 오해 | 바로잡기 |
|---|---|
| 같은 프로그램을 두 번 실행하면 프로그램이 2개 | ❌ **프로그램(파일)은 1개, 프로세스는 2개.** 프로세스는 실행할 때마다 생긴다 |
| exec를 하면 프로세스가 하나 더 생긴다 | ❌ 같은 프로세스 안에서 **프로그램만** 바뀐다 |
| `palloc_get_page (0)`의 0은 "빈 값" | ❌ 옵션 스위치(비트)를 **하나도 안 켰다**는 뜻. `PAL_ZERO`만 켜도 여전히 커널 풀 |
| exec 성공 시 `process_exec`가 0보다 큰 값을 돌려준다 | ❌ **아무 값도 안 돌려준다.** 성공은 값이 아니라 점프(`do_iret`)로 끝난다 |
| exec 후 fd가 남는 건 `load` 덕분 | ❌ **아무도 안 지워서** 남는다. fd 테이블은 `process_cleanup`이 지우지 않는 `struct thread`에 있다 |
| 관리자 승인을 받으면 유저 프로그램도 커널 메모리를 읽을 수 있다 | ❌ 관리자는 OS가 정한 **계정 권한**, 커널 모드는 CPU가 정한 **실행 모드.** 관리자 프로그램도 유저 모드로 돈다 |
| U 비트를 1로 바꾸면 유저도 접근 가능 | ❌ U 비트가 든 페이지 테이블 자체가 커널 메모리(U=0)라 유저는 못 바꾼다. 건드리는 순간 page fault |
| `sys_halt`를 `syscall_handler`보다 위에 두면 먼저 꺼진다 | ❌ 위에서 아래로 **읽는 것(컴파일)** 과 **실행하는 것**은 다르다. 위에 두는 건 컴파일러에게 함수 모양을 미리 알려 주기 위해서 |

> 가장 큰 깨달음: **"누가 지키는가"보다 "누가 지우는가"를 먼저 보자.** `cmd_line`은 지워지는 쪽(유저 메모리)에 있어서 복사해야 했고, fd 테이블은 원래 안 지워지는 쪽에 있어서 아무것도 안 해도 됐다.
